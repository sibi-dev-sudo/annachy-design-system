## 7. Schema / validator extensions

All additive; the 15 R5 fixture manifests keep their expected rule codes.

- **E1** `licence.redistribution` adds `internal-only`; policy P03 accepts it like `allowed`.
- **E2** decision gate may be `{notApplicable: true, date, reference}` (resolved for P02) — used for D-14.
- **E3** `status` adds `restricted` (policy as `active`; root must be under `restricted/`, else N01).
- **E4** optional top-level `root` (`src/icons` default, `restricted/brands`): N01 path convention and the I03 orphan scan use it; originals must be under `<root>/originals/` (`<root>/originals/<source>/` for `src/icons`).
- **E5** file paths may be under `src/icons/` or `restricted/brands/`; originals may be category files shared by many icons — the validator reads/hashes/parses each file once (cache).
- **E6** icon `name` uses `iconName` (`^[a-z0-9]+(-{1,2}[a-z0-9]+)*$`, ≤128) so `--` qualifiers are allowed.
- **E7** optional icon fields `variants` (node id per size), `perSize` (files `<root>/svg/<style>/<name>--<size>.svg`, hash + SVG + path checked), `knownProblems` (`{code, reason}`; listed codes are returned in `recorded`, not as failures).
- **E8** optional top-level `originals` (path, SHA-256, Figma node id per category export): hash-checked and counted as listed for I03 — needed because the duplicate Calender frame's export is referenced by no icon.
